# Security policy

Do not publish credentials, learning archives, session identifiers, delivery targets, or proof-of-concept content containing real child data in an issue or pull request.

For a suspected vulnerability, use the repository's private security-advisory reporting channel when it is enabled. Until that channel is enabled, contact the repository owner through the hosting platform without including secrets; provide reproduction steps only after a private channel is available.

Operators must keep deployment credentials outside the repository and configure an exact static identity mapping. The project does not provide a generic file, browser, shell, or privilege-escalation interface.
